# Agentic Novelty Synthesizer with Web Search

> 소믈리에의 explore 분기를 단발 LLM에서 **웹검색을 활용하는 에이전트**로 진화. corpus 안 지식(LLM training cutoff)에 갇히지 않고, 실시간 최신 기법·SOTA를 조사해 진짜 참신한 recipe를 제안한다.

> 확장 대상: [[cq-tc-autonomous-experiment-loop]] v1. ε-novelty mix의 explore(ε) 분기 구현체를 교체.

## 왜 이 아이디어인가

v1 폐루프의 30-round 실주행에서 explore가 `fashionmnist-mlp`, `cifar10-resnet18` 같은 **LLM이 이미 아는 표준 recipe만** 제안하는 한계가 드러났다. NoveltyRecipeSynthesizer가 단발 LLM completion이라 training knowledge 범위를 못 벗어난다.

웹검색을 붙이면:
- cutoff 이후 최신 기법/아키텍처/SOTA 반영
- "이 데이터셋·intent에 지금 무엇이 좋은가"를 실시간 조사
- corpus가 local optima에 갇혔을 때 외부 지식으로 진짜 새 방향 주입
- 부수 효과: 합리적 hyperparam 범위를 함께 가져와 v1에서 관찰된 "lr 극단 폭주(e-08)" 완화 가능

**재현성과 충돌 안 함**: 재현 대상은 *추천*이 아니라 *추천으로 돌린 실험 결과(evidence)*다. evidence는 여전히 PCQ로 봉인된다. 추천 과정의 비결정성(웹 결과 변동)은 허용되며, 오히려 attribution에 출처를 박아 추적성이 늘어난다.

## 풀고자 하는 문제

**누가**: v1 폐루프를 운영하는 연구자. corpus가 두꺼워질수록 explore가 "아는 것의 재탕"이 되어 다양성이 정체.

**무엇**: explore의 novelty가 LLM training knowledge에 묶여, 진짜 새로운(corpus 밖 + 모델이 모르던) 방향을 못 연다. 폐루프가 "사람이 들여다볼 때쯤 풍부한 사전실험"이 되려면, 그 사전실험이 *최신*이고 *외부 지식*까지 흡수해야 가치가 크다.

## 기존 대안과 차이

| 대안 | 한계 | 우리가 다른 점 |
|---|---|---|
| 단발 LLM novelty (v1) | training cutoff에 갇힘, 표준 recipe 재탕 | 웹검색으로 실시간 최신 기법 |
| 사람이 직접 논문 찾아 recipe 설계 | 시간 비용, 폐루프 자율성 깨짐 | agent가 자율 조사 |
| 고정 recipe 카탈로그 확장 | 수동 관리, 곧 stale | 매 explore가 실시간 |

## 요구사항 (EARS)

### 기능 요구사항

**E1 explore agentic (이벤트)** — WHEN explore 분기가 선택되면, AgenticNoveltySynthesizer가 web_search로 intent·데이터셋 관련 최신 기법을 조사한 뒤 corpus 밖 novelty recipe를 합성한다.

**E2 cold-start 검색 우선 (이벤트)** — WHEN corpus가 cold-start(최초)이면, 첫 추천 전 web_search로 baseline recipe를 조사한다 ("최초의 순간에 검색 먼저").

**E3 stagnation 강제 explore (상태)** — WHILE best_metric이 R(기본 5) round 동안 정체이면, wrapper(cq)가 다음 round를 강제 explore(agentic)로 디스패치한다. 감지는 wrapper의 `loop_state.best_metric`로 (TC는 stateless 유지).

**E4 intent steer 발동 (이벤트)** — WHEN 사람이 intent에 최신 기법 탐색 신호("최신 기법 찾아봐" 등)를 주면, 그 round를 agentic explore로.

**E5 출처 보존 (이벤트)** — WHEN agentic recipe가 ingest될 때, agent가 참조한 검색 출처(URL/논문)를 `attribution.sources`에 보존한다 — lineage 추적성.

**E6 graceful degrade (조건)** — IF web_search 또는 agent가 실패하면, THEN 기존 단발 NoveltyRecipeSynthesizer로 degrade한다 (RR6, 추천 중단 금지).

**E7 검색 비용 cap (특성)** — WHERE 비용 관리가 필요하면, round당 web_search 호출 횟수에 상한을 둔다. cost_meter에 search 비용 계측.

**E8 인터페이스 보존** — AgenticNoveltySynthesizer는 기존 `NoveltyRecipeSynthesizer`와 동일 Protocol(`propose(corpus_recipes, intent) -> NextConfigProposal`)을 만족한다. DI 교체만으로 ε-novelty mix 구조 변경 0.

### 비기능 요구사항

- **재현성**: evidence는 PCQ 봉인 유지. 추천 과정 비결정성은 attribution.sources로 추적 가능하게.
- **비용**: agentic은 explore(~10%)에만 발동 → 비용이 explore 빈도에 묶임. exploit은 기존 싼 단발 유지.
- **degrade**: 모든 외부 의존(web_search, agent LLM) 실패는 단발 novelty → cold_start 순으로 graceful.
- **stateless 정합**: stagnation 상태는 wrapper가 보유. TC `/recommend`는 무상태 유지.

### 범위 외 (Out of Scope)

- exploit 분기의 agentic화 — within synth는 corpus 이력으로 충분, 비용 대비 효익 낮음.
- 웹검색 결과 캐싱/공유 — v1.x에선 매 호출 새로. 캐시는 비용 최적화 후속.
- 다중 search provider 추상화 — OpenAI web_search 단일로 시작.
- 검색 출처의 신뢰도 평가/랭킹 — agent LLM 판단에 위임.

## 리스크

| 리스크 | 심각도 | 초기 대응 |
|---|---|---|
| agent 멀티스텝 비용·지연 → 폐루프 throughput ↓ | 중 | explore(10%)에만 발동, round당 search cap |
| web_search 결과 noise → 무의미한 recipe | 중 | corpus 기존 recipe 대조 + structured output 강제 |
| OpenAI Responses API web_search provider 종속 | 낮 | Protocol 추상화 — 후속에 provider 교체 가능 |
| 검색 기반 추천 비결정성 → 디버깅 난이도 | 낮 | attribution.sources로 "무엇을 보고 제안했나" 추적 |
| stagnation 오판(노이즈) → 불필요한 agentic 발동 | 낮 | R 임계 + best 단조 비교, 비용은 explore에 cap |

## 탐구 중 발견한 인사이트

- **재현성 vs 참신성은 거짓 딜레마** — 추천(비결정)과 evidence(PCQ 봉인)를 분리하면 양립. 출처를 attribution에 박으면 비결정성이 오히려 추적성으로 전환.
- **발동을 explore에 한정하면 비용이 자연 cap** — exploit(90%)은 싼 단발, explore(10%)만 비싼 agent. v1의 ε-novelty mix가 비용 분리를 이미 제공.
- **stagnation은 wrapper가, novelty는 TC가** — 상태(best 정체)는 폐루프 host(cq/wrapper)가 보유, 합성은 TC가. v1의 "cq=주체, TC=passive" 분담 유지.
- **인터페이스 1개만 안 바뀌면 진화가 싸다** — NoveltyRecipeSynthesizer Protocol 덕에 단발→agentic이 DI 교체.
