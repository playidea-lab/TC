## 왜 이 아이디어인가

지금까지 PoC는 MNIST + 단일 train_mnist.py(recipe 무시)였다. agentic이 다양한 recipe를 제안해도 실행은 동일 → "다양한 추천 + 동일 실행"의 벽. 검증하려는 진짜 가설은 **"자율 코드생성 루프(CQ+PCQ+TC)가, 모델마다 학습 방식이 완전히 다른(=진짜 다양한 코드가 필요한) 시나리오에서 작동하는가"**다.

dental segmentation은 그 시험대다 — V9(2D multi-view), pointnet2, diffusionnet, tsegformer, crosstooth(point transformer), dgcnn 등 접근마다 코드가 완전히 다르다. 그리고 사용자의 실제 연구(KSH 연세대-오라픽스)라 8시간 결과가 버려지지 않고 실용적이다.

## 검증 대상 / 성공 기준

"높은 mIoU"가 아니라 **자율 코드생성 루프의 작동 여부**:
1. **(1차) 코드 생성 성공률** — round별 "실행됨/깨짐" 비율이 corpus가 쌓이며 오르는가
2. 코드 진화 깊이 — lineage에서 derives_from 체인이 실패→수정→성공으로 이어지는가
3. 최고 mIoU 도달 — 결국 baseline(0.7870)에 근접/돌파하는가

→ 셋 다 8시간 trace로 보되 1차 기준은 (1).

## 핵심 컴포넌트 의미 (코드생성 방식에서)

- **CQ** = 생성 코드의 실행기. 4090 워커에서 timeout 걸고 격리 실행, stdout `@miou=` 파싱.
- **PCQ** = 생성 코드를 재현 가능한 계약으로 봉인. `code.content_sha256` + 생성 train.py 본문 vendoring. "이 mIoU는 정확히 이 생성 코드로 나왔다"의 감사 단위. **코드가 매번 다르므로 vendoring이 비로소 핵심.**
- **TC** = 코드 진화의 메모리. 도서관 = (생성 코드 + 결과 + **실패 traceback**) corpus. 소믈리에 = 그 corpus를 컨텍스트로 다음 train.py 생성. lineage = 코드 진화 트리(derives_from=개선/디버그, exploration=새 접근).

## 요구사항 (EARS)

**E1 코드 생성 (이벤트)** — WHEN explore/cold-start/stagnation 분기가 선택되면, agentic이 (a) `~/dental_data` 디렉토리 목록 + (b) 웹검색(dental seg SOTA 2024-2025) + (c) TC corpus(이전 코드+결과+실패)를 컨텍스트로 **train.py 전체 + requirements**를 생성한다.

**E2 실행 (이벤트)** — WHEN 생성 train.py를 받으면, cq가 4090 워커에서 `uv run --with <requirements> python train.py --data-root ~/dental_data`를 timeout 걸고 실행, stdout `@miou= @iou_tooth= @iou_gum=`를 파싱한다.

**E3 PCQ 봉인 (이벤트)** — WHEN 실행이 끝나면(성공/실패 무관), 생성 코드 sha256 + 코드 본문 vendoring + 결과(또는 실패 traceback)를 PCQ envelope으로 봉인한다.

**E4 TC 적재·환류 (이벤트)** — WHEN envelope을 ingest할 때, code+metrics+실패를 corpus에 적재하고, 다음 생성 시 소믈리에가 이를 컨텍스트로 제공한다.

**E5 lineage (이벤트)** — exploit=derives_from(이전 코드 개선), explore=exploration(새 접근). 코드 진화 트리.

**E6 성공률 추적 (상태)** — WHILE 루프가 도는 동안, round별 (실행성공/실패/best_miou)를 영속 추적, 매 N round 알림.

**E7 안전 가드 (특성)** — WHERE 무인 8시간이 필요하면, per-run timeout(예: 20분), 동적 의존성은 생성 requirements로 `uv --with`, 실패는 evidence로(폐루프 중단 금지).

**E8 8시간 무인 (상태)** — WHILE 8시간 동안, state 영속(재시작 이어받기), cq 워커 끊김 시 graceful(다음 round).

### 비기능
- **재현성**: 생성 코드 vendoring + data_ref(`~/dental_data` 경로/내용 해시) → evidence 봉인.
- **비용**: agentic(웹검색+코드생성, gpt-4o)은 explore/stagnation에만. 학습은 round당 수 분~수십 분이라 8시간에 round 수십 → agentic 호출 적당.
- **안전**: 본인 4090·본인 데이터라 보안보다 안정성(timeout/OOM/디스크).

### 범위 외
- 좋은 mIoU 자체(검증 대상은 루프 작동).
- exploit의 처음부터 코드 재생성(within은 직전 성공 코드 변형이 자연).
- 데이터 형태 사전 명세(자율 탐색).
