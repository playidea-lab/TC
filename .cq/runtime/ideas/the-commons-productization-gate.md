# The Commons — Productization Gate Cycle

> TC를 cq-only Phase-1에서 독립 서비스로 개방하는 *조건*을 결정화한다.
> 비전은 "단계적 개방"만 적었고 그 트립와이어는 비어 있었다 — 이 /pi가
> 채운다. [[the-commons-success-metrics]] 연장.

## 왜 이 사이클인가

대화에서 "도서관 서비스화 vs cq 단독 연결"이 either/or가 아니라 *순서*
문제임이 드러났다. 비전 카드는 TC를 "cq의 기능이 아니다"·"단계적 개방"
이라 못 박았고, 팔란티어 모델(플랫폼이 곧 제품)은 서비스화를 *목적지*로
만든다. 그러나 *언제 플립하나*의 게이트가 미정의였다. bare verdict는
"기전이 내부 시드 1건으로 동작"으로도 통과 → 검증 안 된 추천을 외부에
노출하는 조기제품화 리스크. 게이트는 verdict보다 *높아야* 한다.

## 결정화한 게이트 (Canonical)

> TC는 다음 **세 조건이 동시 충족**될 때만 cq-only에서 독립 서비스로
> 플립한다 — (1) **강화된 성공**: 3-event verdict가 성공이며 그중
> *external-origin ≥ 1*, (2) **코퍼스 밀도 바닥**: 추천 대상 cluster들이
> real-evidence 우세(synthetic 미지배), (3) **추천 품질 바닥**:
> *재현 promote-rate proxy* 가 최소 재현 건수 위에서 지속적으로 바닥
> 이상. 미충족 시 매 verdict window마다 조건별 진단을 방출하고, 경계
> window 수 무트립이면 강제 재결정{연장 / 바 하향+근거 / 피벗 / 종료}.

## 확정 결정

### G1. 게이트 = 별개·더 높은 바 (bare verdict 아님)

서비스화 = "낯선 사용자에게 반복적으로 자기 추측보다 나은 추천"이라는
*품질·외부·밀도* 주장. verdict 성공("루프가 닫힐 *수* 있다", 내부 시드
1건 가능)과 다른 claim. 게이트는 조기제품화 리스크("검증 안 된 추천 +
얇은 코퍼스를 외부 노출")를 직접 부정해야 하므로 verdict보다 높다.
**정성-최소 원칙 유지** — success-metrics 카드의 "자의적 양적 임계 거부,
정성 ≥1"을 계승, 숫자를 발명하지 않는다(아래 조건은 정성 서술).

세 조건:
- **C1 강화된 성공**: 기존 verdict 계기 재사용. 3-event 성공 + external-
  origin event ≥ 1 (이미 outreach_origin 라벨·강화된 성공 정의 존재).
- **C2 코퍼스 밀도**: 추천이 닿는 cluster들이 real-evidence 우세
  (synthetic-dominant 아님). 기존 `retirement_real_threshold`·infogain
  regime 임계와 같은 밀도 개념 — 새 상수 신설 회피.
- **C3 추천 품질**: G2 참조.

### G2. 품질 바닥 = 재현 promote-rate proxy

infogain-reranker 사이클이 *진짜 평가 프레임("단일 정답 부재")을 v0.2로
연기*했다 → 측정 못 하는 걸로 게이트 못 검. 이미 계측되는 유일한
outcome-근거 신호 채택: **verification-by-reproduction**(verdict 3 event
중 하나)의 promote/contradict. 품질 바닥 = *최소 재현 N건 위에서 지속된
promote-rate ≥ 바닥*. 단일 promote가 아니라 *지속* (small-N 노이즈 방어).
external 재현자의 promote = 최강 신호(C1과 합성). 진짜 평가 프레임은
게이트를 막는 선결이 아니라 proxy를 *대체하는 v0.2 업그레이드*.

### G3. escape = 진단구동(b) + 경계 시한 재결정(a)

게이트는 "안 열렸을 때 동사"가 없으면 새장. 매 verdict window 미트립 →
*조건별 진단*(C1/C2/C3 중 무엇이 왜 실패) 자동 방출, 기존 verdict 보고서
메커니즘 재사용(internal/external 분리·cluster real-dominance 이미 산출).
경계 window 수 무트립 → 강제 재결정 {연장 / 바 하향+근거 / 피벗 / 종료}.
"경계 window 수"는 품질 바가 아니라 *결정 cadence*(카드가 "3개월"을
process로 박은 것과 동류)라 정성-최소 철학과 정합. (b) 단독은 영구
drift, (a) 단독은 느린-by-design 도서관에 조급 sunset → 결합.

### G4. cq 결합 = 채널이지 새장 아님 (코드 이미 정합)

TC는 이미 독립 FastAPI 서비스(자체 8 endpoint·자체 PG·Protocol). "cq 뒤에
숨김"은 *접근 정책*이지 아키텍처 제약 아님. 게이트 트립 시 추가 재작업
없이 채널 개방 경로가 열려 있음. 서비스화 = 배포 토폴로지
([[the-commons-deployment-corpus-durability]] A+) 위에 외부 접근·테넌시·
남용방어·과금을 *그때* 더하는 것 — 지금 짓지 않는다.

## 요구사항 (EARS)

- **PG1** WHEN verdict window가 종료될 때, 시스템은 C1·C2·C3 게이트 조건
  충족 여부를 verdict 보고서에 *조건별로* 산출·기록한다.
- **PG2** WHEN C3를 평가할 때, 재현(promote/contradict) 이벤트에서 최소
  재현 건수 위 promote-rate를 산출한다. 미달 재현 수면 "측정 불가"로
  명시(거짓 통과 금지).
- **PG3** WHILE 세 조건이 동시 충족되지 않는 동안, TC는 cq-only를 유지
  하며 외부 접근을 열지 않는다.
- **PG4** WHEN window가 미트립으로 종료될 때, 어느 조건이 왜 실패했는지
  진단을 보고서에 방출한다 (부분성공 경로와 동형, actionable).
- **PG5** IF 경계 window 수 연속 무트립이면, 강제 재결정 항목{연장/바
  하향+근거/피벗/종료}을 verdict 보고서에 *결정 요구*로 표기한다.
- **PG6** WHEN 세 조건 동시 충족(트립)될 때, 보고서는 "서비스화 게이트
  통과"를 명시하고 플립은 owner의 명시 결정으로 남긴다(자동 개방 금지).

## 범위 외 (v0.2 / owner)

- 양적 임계 확정값(promote-rate 바닥·최소 재현 N·경계 window 수) — 출시
  *후* 첫 데이터로 보정 (success-metrics 철학: 사전 자의적 숫자 거부)
- 진짜 추천-품질 평가 프레임 (offline counterfactual) — proxy 대체 v0.2
- 외부 접근 표면: 공개 API 하드닝·멀티테넌시·남용/rate·과금·SLA·PHI
  표면 확대 — 게이트 트립 *후* 설계
- 실제 플립 결정·GTM — owner 비즈니스 결정 (게이트는 신호, 결정 아님)

## 탐구 중 인사이트

1. 서비스화 vs cq-only는 either/or 아니라 *순서* — 비전이 절반 답해놨다
   ("cq 기능 아님"·"단계적 개방").
2. bare verdict ≠ 제품 준비 — "기전이 동작"과 "외부에 반복 좋은 추천"은
   다른 claim.
3. 품질 바닥이 게이트의 현실성을 결정 — 측정 도구(평가 프레임)가 미해결
   이라 proxy 없으면 게이트가 공허. proxy는 도피가 아니라 정직한 v0.1 답.
4. 게이트는 escape 동사 없으면 새장 — "안 열렸을 때"가 게이트의 절반.
