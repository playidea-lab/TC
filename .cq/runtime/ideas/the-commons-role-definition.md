# The Commons — Role Definition Cycle

> TC의 역할을 한 문장으로 못 박는다. "library + match-maker" 이중 정체성을
> 깨고, 매치메이커의 목적함수까지 정의한다.

## 왜 이 사이클인가

v0.1 코드 안정화·페이지 게시까지 끝났는데도 사용자가 같은 질문을 반복했다 —
"TC는 실험계획기 같은거지? / stateless rag 서버야? / 최적 기록 추천이지?".
이 반복은 **역할의 이중 정체성("library + match-maker")이 아직 안 풀렸다**는
신호였다. 이번 사이클은 새 기능이 아니라 *정체성의 하중점*을 정한다.

## 결정화한 정의 (Canonical)

> **TC는 cross-user ML 실험 매치메이커다.** 무상태 advisor로서 "이 문제 +
> 이 리소스"를 받아, *그 문제 영역의 불확실성을 가장 줄이는 다음 실험*을
> 음성·실패 evidence를 명시적 근거로 삼아 랭킹한다. evidence 도서관
> (L1 불변 / L2 추가 / L3 큐레이션)은 목적이 아니라 정보이득 추천을
> 가능케 하는 **기전**이다. 사이클 상태는 cq가 보유, TC는 매 호출 무상태로
> 사실·근거만 반환 — 정책은 호출자가 결정.

## 이번 사이클의 확정 결정

### D1. 하중 정체성 = 매치메이커 (도서관은 기전)

"library + match-maker" 하이픈을 깬다. 도서관 단독(코퍼스·불변성·큐레이션)은
raw record가 붙은 Papers-with-Code일 뿐 — 비전이 기대는 차별점(음성이 검색
공간을 좁힘, synthetic 자동 retire, loop closure)은 전부 *추천을 통해서만*
결실한다. 따라서 모든 설계 판단의 결정 기준은 단 하나: **"이게 랭킹을
개선하는가?"** L3 큐레이션·lineage·reciprocity도 이 렌즈로 평가된다.

- 트레이드오프 인지: "ML evidence의 위키피디아" 공공재 서사가 약해진다.
  contributor-귀속 거버넌스 명분(CDLA·"PI Lab 사유 아님")은 도서관 정체성에
  기댔었다. → 거버넌스 약속은 *유지하되*, 그 정당화를 "좋은 추천에는 신뢰
  가능한 공동 코퍼스가 필요하다"로 재정렬 (도서관은 추천의 신뢰 기반).

### D2. 목적함수 = 정보이득 (음성 evidence 명시 활용)

매치메이커가 최대화하는 것은 *기대 metric*(①)도 *코퍼스 성장*(③)도 아닌
**정보이득**: "이 사용자의 문제 영역 불확실성을 가장 줄이는 다음 실험".

- ①(기대 metric 최대화)은 SOTA 추격으로 붕괴 → 음성 evidence 가치 0 →
  vision의 "음성 1급" 약속과 정면 배반. 폐기.
- ③(코퍼스 성장)은 reciprocity와 직결되나 개별 사용자 이익을 희생할 수 있어
  *추천 목적함수*가 아니라 reciprocity 보상 설계로 분리 (v0.2).
- ②만이 "음성이 검색 공간을 좁힌다"를 장식이 아닌 *기전*으로 만들고,
  AutoML/leaderboard와 진짜로 차별화한다.

### D3. v0.1 `/recommend`는 역할의 placeholder다 (정직한 재규정)

현재 빌드: 자연어 직렬화 → embedding → pgvector top-K → Gemini listwise
rerank → 기대 적합도 순 top-N. 이는 사실상 ①(기대 metric 추천)이다.
D2가 확정된 이상 **v0.1 추천 경로는 정보이득 목적함수의 placeholder로
재규정**된다 — 폐기가 아니라, retrieval/직렬화/저장 기반은 유효하고
*reranker의 목적함수*가 교체 대상.

## 요구사항 (EARS)

### 기능

- **RD1** WHEN cq가 /recommend를 호출할 때, TC는 후보 실험을 *정보이득*
  (문제 영역 불확실성 감소 기대치) 기준으로 랭킹한다. 기대 metric 단독
  순위를 1차 기준으로 쓰지 않는다.
- **RD2** WHEN 후보를 랭킹할 때, 관련 음성·실패 evidence를 검색 공간 축소
  신호로 *명시적으로* 점수에 반영하고, 응답 근거에 음성 evidence를 caveat로
  인용한다.
- **RD3** WHILE TC가 응답할 때, 무상태를 유지한다 — 사이클 상태를 보유하지
  않으며 사실·랭킹·근거만 반환하고 정책 결정은 호출자에게 위임한다.
- **RD4** WHERE 도서관 기능(L1/L2/L3·큐레이션·lineage)의 설계 판단이
  필요할 때, "정보이득 랭킹을 개선하는가"를 채택 기준으로 적용한다.
- **RD5** IF v0.1 기대-metric rerank 경로가 사용될 때, 이를 정보이득
  목적함수의 잠정 구현(placeholder)으로 문서·메타에 표기한다.

### 비기능

- **정직성**: 빌드와 명세의 간극(placeholder)을 숨기지 않고 페이지·llms.txt·
  manifest에 명시한다.
- **차별성**: 정보이득 목적함수가 AutoML/leaderboard와의 차별의 *유일한*
  하중점임을 메시징 전반에서 일관 유지.
- **무상태성**: 정보이득 계산이 cq 측 사이클 상태를 TC로 끌어오지 않도록
  입력은 (problem + resource + evidence hints)로 self-contained.

### 범위 외 (다음 사이클)

- 정보이득 추정 알고리즘 구체 설계 (Bayesian/active-learning 형태, feature)
- 정보이득 추천의 평가 메트릭 정의 ("recipe가 이겼다" 단일 지표 부재 문제)
- reciprocity(③ 코퍼스 성장)와 추천 목적함수의 결합 지점
- v0.1 rerank → 정보이득 reranker 마이그레이션 운영 계획

## 탐구 중 발견한 인사이트

1. **이중 정체성은 미해결의 증상이다** — 사용자의 반복 질문이 곧 하이픈이
   안 풀렸다는 진단. 역할 정의는 새 결정이 아니라 *증상의 봉합*.
2. **목적함수가 역할의 진짜 정의다** — "근거 있는 랭킹"은 형태일 뿐.
   무엇을 최대화하는지 정해야 비로소 역할이 완성된다.
3. **역할 정의가 빌드를 재규정한다** — D2 확정이 v0.1을 placeholder로
   바꿨다. 정의는 회고가 아니라 빌드 위상을 정하는 행위.
4. **차별점은 단 하나에 하중을 둔다** — 정보이득(②)이 AutoML 대비 차별의
   유일한 기둥. 나머지(도서관·reciprocity)는 이 기둥의 보조구조.
