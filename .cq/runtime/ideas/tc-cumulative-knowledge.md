# PCQ-CQ-TC 누적지식 시스템 — 과거는 시스템이, 미래는 에이전트가

> 검증된 실험을 지식그래프로 쌓고(불변), 그 위에서 귀납지식(추세·계보·실패)을 *순수계산*으로 정제해 에이전트에게 환류한다. 판단·창조는 에이전트가, 기억·계산은 LLM-free TC가. [[the-commons-vision]]·[[the-commons-role-definition]]의 재정의, [[pcq-cq-tc-5h-robustness-findings]]가 데이터로 촉발.

## 왜 이 아이디어인가

5시간 폐루프 검증(MVTec bottle→screw, 10라운드 무중단, screw 0.86→0.96)이 두 가지를 데이터로 드러냈다:

1. **폐루프를 실제로 닫은 건 추천(`tc_recommend`)이 아니라 환류(`tc_recent_attempts`)였다.** 추천(LLM이 에이전트 대신 next_config 합성)은 category-blind·quota 429로 약했고, 환류(정확한 과거 제시) + 에이전트 판단이 SOTA를 만들었다. → **시스템이 에이전트를 *대체*하려 들면 진다.** 시스템 내부 LLM은 항상 세션 에이전트보다 맥락이 적기 때문.
2. **corpus가 10건으로 늘어도 시스템은 더 똑똑해지지 않았다.** 사실은 쌓이는데 *지식*(패턴)으로 전환하는 레이어가 없다. "memory↑→auroc↑"라는 교훈은 에이전트 머릿속에만 남고 시스템엔 안 남았다. → **현재는 "데이터 레이크"이지 "지식 베이스"가 아니다.**

"에이전트를 위한 시스템"이라면 가치는 *에이전트를 증폭*하는 데 있다. 이 아이디어는 TC를 "소믈리에(처방)"에서 "사서+분석가(기억+계산)"로 재정의해, **시간이 지날수록 강해지는 누적지식 시스템**으로 만든다.

## 풀고자 하는 문제

harness 위의 에이전트(Claude Code)는 구조적으로 셋이 약하다 — **환각**(자기 코드 검증 불가), **휘발성 기억**(세션 종료 시 망각), **로컬 한계**(실행). PCQ-CQ-TC가 각각 보철이다. 그러나 현재 TC는 사실을 *나열*만 하고 *지식*으로 정제하지 못해, 매 세션 에이전트가 raw 사실에서 패턴을 재추론한다. 누적지식이 안 되니 "시간이 지날수록 강해진다"가 성립하지 않는다.

## 기존 대안과 차이

| 대안 | 한계 | 우리가 다른 점 |
|------|------|--------------|
| 에이전트 메모리 / 긴 컨텍스트 | 휘발·한정·검증 안 됨 | **PCQ 봉인된 검증 사실** + 세션·에이전트 간 공유 |
| 일반 RAG | 문서 검색일 뿐, 패턴 없음 | **귀납계산**으로 사실→추세·계보·실패 |
| 추천 시스템(처방) | 시스템이 대신 결정 → 맥락 부족 | **처방 없음** — 판단은 맥락 풍부한 에이전트 |
| 형식 온톨로지(OWL/RDF) | top-down 설계, 도메인 진화에 깨짐 | **최소 구조 + 데이터 귀납**으로 온톨로지 *창발* |

## 4주체 재정의

| 주체 | 정체성 | 한다 | 안 한다 |
|------|--------|------|--------|
| **에이전트** | 창조자·판단자 (미래) | train.py 창조 · 환류 읽고 판단 · 맥락 통합 · E&E 도약 | 검증 주장·로컬 실행·과거 암기 |
| **PCQ** | 봉인자 (주장→증거) | describe_run으로 effective config 실측 봉인 | 추천·저장·판단 |
| **CQ** | 원격 실행 팔 | 코드 디스패치·config 주입·결과 회수 | 코드 생성·봉인·저장 |
| **TC** | 누적지식 시스템 (기억+계산, **LLM-free**) | 그래프 적재(불변)·귀납계산·환류 | **처방·판단·LLM 호출** |

한 사이클: `에이전트[창조] → CQ[실행] → PCQ[봉인] → TC[기억+계산] → 에이전트[판단] ↺` — corpus가 자랄수록 귀납지식 정밀 → 에이전트 판단 강화 = **harness 위 무한 E&E**.

## 요구사항 (EARS)

### 지식그래프 (기억)
- **KR1** WHEN 에이전트가 evidence 계보를 요청하면, TC는 lineage 엣지를 순회해 조상 사슬을 반환한다.
- **KR2** evidence는 append-only이며, 어떤 귀납 계산도 원본을 변경하지 않는다(파생만).

### 귀납지식 (계산)
- **KR3** WHEN 환류를 요청하면, TC는 같은 recipe evidence들에서 numeric config 축별 metric 추세(단조성)를 순수계산해 반환한다.
- **KR4** WHEN 환류를 요청하면, TC는 실패 evidence들의 공통 config·에러 패턴을 집계해 반환한다.
- **KR5** config 축은 numeric/categorical/target 타입으로 표시되며(최소 온톨로지 씨앗), 추세 계산은 이 타입으로 비교 가능 축을 식별한다. 형식 온톨로지는 설계하지 않는다.

### 경계 (증폭 ≠ 대체)
- **KR6** TC의 환류·귀납 출력에는 처방 필드(next_config 등)를 포함하지 않는다 — 코드 레벨로 강제.
- **KR7** 기존 LLM 처방 추천(within/novelty synth·infogain prior·reranker)은 제거하거나 cold-start/explore 보조로 격하하며, 폐루프 주경로는 환류 기반 에이전트 판단이다.

### LLM-free TC
- **KR8** TC의 기억·계산·검색은 외부 LLM API를 호출하지 않는다. 의미검색은 로컬 임베딩(**BGE-m3**)으로 수행한다.
- **KR9** WHEN 임베딩 모델을 교체하면, 기존 evidence는 idempotent re-embed로 새 임베딩 공간에 정렬된다(`reembed_corpus.py` 재사용, 로컬이라 quota 없음).

### 검증 가능성
- **KR10** 귀납 계산은 순수 함수로 구현되어 "evidence 입력 → 기대 패턴" 단위 테스트로 검증된다(5h 데이터를 픽스처로). → 처음으로 "시스템이 올바른 지식을 뽑는가"를 객관 측정.

### 비기능
- **성능**: 귀납은 조회 시 계산(on-the-fly, corpus 작으니 YAGNI). BGE-m3 임베딩은 M4 Max MPS에서 로컬.
- **강건성**: TC는 결정론적·quota-free. LLM 장애가 TC 기능을 막지 않는다.

### 범위 외 (2단계/미래)
- 논문 파싱 등 **문헌지식(미검증)** 통합 — 별도 `literature` tier로 격리, 검증된 실험지식이 단단해진 후.
- 전용 벡터DB(Qdrant/Milvus) 전환 — pgvector 한계(벡터 수·p99 latency 임계) 도달 시. 트리거만 기록.
- 횡단 보편 온톨로지 — 데이터가 쌓이며 창발(설계 아님).

## 탐구 중 발견한 인사이트

1. **대체는 지고 증폭이 이긴다** — 시스템 내부 LLM은 세션 에이전트보다 항상 맥락이 적다. "에이전트를 위한 시스템" = 에이전트를 대신하지 말고 정확한 재료를 줘라.
2. **누적(사실) ≠ 강해짐(지식)** — 일기장은 100장이어도 안 똑똑해진다. 사실→패턴 전환 레이어가 핵심.
3. **지식 두 종류** — 구조적(계산 가능, 싸다, 시스템) vs 해석적(맥락 의존, 에이전트). 이 선을 넘으면(처방) 추천의 실패 반복.
4. **corpus는 본질적으로 과거** — "아직 안 해본 것"은 corpus에 없다. 미래의 도약은 영원히 에이전트 몫.
5. **처방을 버리면 TC는 LLM-free가 된다** — 합성·prior·rerank·explore가 다 처방 부속. 남는 건 검색용 임베딩뿐이고 그마저 로컬화하면 quota 병목(5h 429) 근본 소멸.
6. **온톨로지는 목적지이지 출발점이 아니다** — top-down 설계(시맨틱웹 전철) 금지, 데이터가 bottom-up으로 길러낸다.
7. **순수 계산이라 테스트 가능** — 귀납을 LLM 아닌 산수로 두는 덕에 "시스템이 가치 있는가"를 단위 테스트로 처음 검증 가능.
